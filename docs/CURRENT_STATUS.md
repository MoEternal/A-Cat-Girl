# 当前实现状态

更新日期：2026-07-31

## 已完成

- 管理控制台已增加单管理员登录：首次打开创建账号，之后使用持久化 HttpOnly 会话登录；账号创建后统一保护 `/api` 管理接口，OneBot 连接仍使用独立令牌。
- FastAPI + SQLite 后端和 Vue 3 + TypeScript 管理界面。
- API 供应商创建、编辑、启停、删除、切换和 `/models` 连通性测试。
- API 供应商支持 1-10000 故障转移序号。当前组合预设选中的供应商先尝试，之后按序号尝试其余已启用供应商；每个供应商失败时都会向当前 QQ 会话发送“API配置·失败接口 调用失败，故障转移至 API配置·下一接口（此消息在60秒后自动撤回）”。最后一个也失败时发送包含错误类型、HTTP 状态、错误消息和响应正文的完整报错，同样在 60 秒后自动撤回。
- API 供应商只保存连接、密钥和模型，不再混入生成参数。
- API Key 使用项目本地 Fernet 密钥加密，读取接口只返回掩码。
- 提示词模板创建、编辑、删除和切换。
- 提示词块的 `system`、`user`、`assistant` 角色、启停、拖动排序和完整顺序校验。
- 提示词块兼容 SillyTavern 的 identifier、动态 marker、相对位置和聊天插入深度/顺序。
- 已按 SillyTavern 当前 `release` 分支的宏注册表建立统一宏引擎，目录包含 88 项可插入宏；覆盖名称/人设、角色字段、聊天、token、时间、随机/骰子、条件、变量、Instruct 和官方别名。
- Prompt 预览与纯 Prompt 编译器共用宏引擎；`{{user}}` 和 `{{persona}}` 来自当前用户人设，聊天运行时变量使用明确预览值。
- 插件运行时自行注册的扩展宏不会伪造结果：保留原串并列入未解析列表，等对应插件能力明确实现后再注册。
- 大型模板的块列表、编辑器和发送预览独立滚动；预览卡片不会被压成细条，内容框默认止于视口底部，提示词内容框不再显示手动缩放柄。
- 当前人设变量编译和“实际发送预览”。
- 人设创建、编辑、删除和切换。
- 用户人设作为独立资源，支持名称、描述、主提示/作者注释顶部或底部/指定深度/不自动插入、深度和角色；组合预设保存其引用。
- 世界书及条目创建、编辑、删除；支持主/辅助关键词、常驻、选择性逻辑、概率、0-7 插入位置、深度、角色和顺序。条目列表按插入顺序数字从小到大自动重排。
- 世界书新增全局/角色作用范围，默认角色范围并关联当前角色；角色页可直接链接多本世界书。运行时合并组合预设、当前角色和全局世界书并去重。
- 组合预设创建、复制、编辑、删除和整套切换。
- 每套预设引用一个 API 供应商、一个提示词模板、一个人设和多本有序世界书；激活预设会统一切换整套资源。
- 支持 SillyTavern Chat Completion 预设、V1/V2/V3 角色卡 JSON/PNG、独立世界书和角色卡内嵌世界书导入。PNG 可解析 `chara`/`ccv3` 的 `tEXt`、`zTXt`、`iTXt` 元数据；当前导入卡片文本，不保存立绘。
- Chat Completion 导入优先使用全局 `character_id=100001` 的 `prompt_order`，兼容旧 `100000`；未进入所选顺序的 Prompt 自动进入折叠收纳栏并从编译和预览排除。同批预设、角色卡和世界书会自动建立组合预设关联。
- 预设、API 配置、提示词模板、用户人设、角色卡、世界书、聊天记录和记忆系统状态均可导出 JSON；支持 File System Access API 时由用户选择目标文件夹，不支持时回退到浏览器下载。API 配置仅在显式导出操作中返回完整 Key。
- Prompt 编译器支持世界书关键词/辅助关键词/概率筛选、世界书前后 marker、聊天历史 marker，以及 Prompt/世界书按深度插入。
- 在供应商、提示词或人设页面单独切换资源时，会回写当前预设对应的引用。
- 预设保存上下文解锁/长度、最大回复、候选数、流式、Temperature、Frequency/Presence Penalty、Top P。
- 预设保存引用包裹、继续预填充、系统消息压缩、函数调用、图片/质量、思维链请求和推理强度。
- 已加入独立图片安全模块：CQ image/mface URL 提取、真实 MIME 探测、3.5 MB 请求字节上限、每轮最多 4 张、4 MP/4096 边长限制、GIF 首帧、base64 请求构造与历史占位符隔离。
- 历史内容和 token 估算会拒绝被字符串化的 `data:image/...;base64`，图片只允许在单次模型请求的结构化 content 中出现。
- 已加入公开 Python 插件系统：插件清单、设置 Schema、独立持久状态、同步/异步事件钩子、周期任务和结构化动作均使用同一套 `catgirl.plugins` API。
- 插件管理页支持 ZIP 安装、启停、动态设置、重载、卸载、权限声明和最近错误；明确提示插件与服务器进程同权限运行，不伪装为安全沙箱。
- ZIP 安装器限制 32 MB 压缩包、128 MB 解压体积和 1,200 个文件，拒绝路径穿越、符号链接、多清单、越界入口与覆盖内置插件。
- 主动回复、睡眠模拟和表情回复均作为内置插件实现，没有后端特判。主动回复保留随机 10-60 分钟、最多两次、暂停/恢复；睡眠模拟保留双方确认、7.5-9 小时休眠和暂存消息；表情保留 10% 提示概率、标签解析、`|||` 分段和直接索要。
- 已从旧项目只迁移 19 类、398 个表情文件和分类说明。插件动作只保存受控文件引用，晚安缓冲只保存文本与媒体引用，状态层拒绝 base64。
- 已实现原创内置插件“记忆系统”，单人和多人剧情共用同一套结构化记忆模型；按聊天记录隔离人物、事实、承诺、物品、支线、事件与归档摘要，并用证据片段、定期细节审计和本地相关性召回降低长期剧情中的细节遗漏。插件默认关闭，由用户确认配置后启用。
- 插件 API 已增加按聊天记录持久化状态、受权限控制的历史读取和静默模型分析；静默分析不会向 QQ 发送消息，也不会写入正式聊天历史。
- 插件管理 API 已增加通用只读状态检查接口 `GET /api/plugins/{plugin_id}/conversation-states`，可按聊天记录选择并只返回一份状态正文，避免一次加载所有大型插件状态。
- 插件管理 API 已增加通用全局状态读写接口 `GET/PUT /api/plugins/{plugin_id}/state`。插件可以提供状态规范化和校验方法，管理端无需为具体内置插件增加专用业务路由。
- 已新增第九个内置插件“正则”，默认常驻但不预置任何脚本。管理页分别维护全局规则和按角色卡 ID 隔离的角色规则；每条规则独立启停、排序，支持替换文本和 `i/m/s` 标志，保存时校验表达式语法，执行时限制单条正则耗时。
- `before_send` 钩子已正式接入 OneBot 文本发送边界。正则只改变发给 NapCat 的文本，模型回复、聊天历史、控制台和持久动作仍保留原文；生成动作会固化角色卡 ID，避免延迟发送时误用后来切换的角色规则。
- 记忆系统管理页已增加原创“细胞网络”可视化：以当前视角为中心、角色以可点击的有机细胞节点环绕呈现，虚线表示与当前视角的关系、实线表示角色间明确关系。点击角色可查看人物档案、社交关系、重要事件、任务约定和关联物品；空记录和手机宽度均可正常使用。
- 记忆整理器已扩展角色稳定档案字段（体貌、性格、职业、兴趣、偏好、住处、重要信息、对用户关系/态度）和有证据的角色关系边，旧状态兼容保留，新字段只随明确剧情事实增量更新。
- 记忆插件源码和通用插件清单内已定义空白表结构，覆盖时空、角色档案、关系、任务约定、事件和物品；即使尚无聊天记录，管理页也直接显示六张只有表头和空白行的表，而非等待首轮整理的提示。
- 插件管理页每项设置均提供鼠标悬浮说明；所有输入框、文本框和下拉框的编辑字体统一缩小，提示词标题输入也相应缩小。
- 数值型插件设置会从 Schema 自动显示最小值和最大值，并把允许范围同步写入鼠标悬浮说明与输入控件约束；记忆系统全部数值参数已覆盖。
- 版本号已更新为 `1.0.1`。侧栏品牌图、浏览器标签页、WebView 窗口、EXE 和任务栏图标均替换为用户提供的同一版猫娘图片；PNG 保留原始白底黑边，未增加背景或其他视觉处理。
- 已实现 OpenAI 兼容 Chat Completions 客户端：普通 JSON 与 SSE 流式响应、文本/推理/usage 解析、超时、协议错误和 API Key 回显脱敏。
- 已增加 `conversations`、`chat_messages`、`runtime_actions` 三类运行数据；同一会话模型请求串行，不同会话可并发。
- 消息运行时已接通用户消息、插件消费、Prompt/宏/世界书编译、最旧历史裁剪、当前预设、模型生成、响应插件和待发送动作。
- 插件 `request_generation` 使用当前选定供应商并通过持久队列执行；临时提示不会写入正式历史。服务重启会恢复中断的动作状态。
- 已开放内部诊断 API：`POST /api/runtime/messages`、会话/消息查询和动作查询。它没有网页聊天入口，但调用消息接口会真实请求当前供应商。
- 已实现 NapCat/OneBot 11 反向 WebSocket：访问令牌鉴权、连接账号状态、私聊/群聊开关、允许名单、事件持久去重和 echo 响应匹配。
- OneBot 私聊文本已接入统一消息运行时；`send_text` / `send_image` 会执行 `send_private_msg` 或 `send_group_msg`，离线时保持 pending，重连后重新排队。
- 当前安装通过可单独启停的全局正则隐藏完整 `<Thinking ...>...</Thinking>` 块；OneBot 出口仍固定隐藏单独的 `<!-- Test Inputs Were Rejected -->` 标记。过滤为空时静默完成动作，不向 QQ 发送空消息，数据库历史和控制台保留原文。
- 聊天记录会把模型 API 原生返回的 reasoning/thinking 字段显示为每层内默认收起的“思考过程”折叠块；提示词中的 `<thinking>` 仍只是普通文本标签，不会被当作模型原生思考过程。
- QQ 文本按 4,000 字符分段；表情回复的 `|||` 保持多段发送。图片发送只接受数据/插件目录内受控文件路径，不将 base64 写入动作或历史。
- QQ 收图已接入 CQ image/mface URL 下载：每条最多 4 张、16 MB 源文件、真实 MIME、64 MP 源像素、4 MP/4096 请求尺寸和约 3.5 MB 规范化上限；GIF 转静态 PNG。
- 规范化图片只覆盖本轮最后一条 user 请求为结构化多模态 content；SQLite 历史只写 `[图片N: 文件名]`、文本和相对媒体引用，下一轮不会携带旧 base64。
- 已新增“QQ 接入”管理页，支持反向 WebSocket 地址复制、加密令牌、启停、私聊/群聊、允许名单、调用超时和连接/待发送/失败状态。
- 已新增“聊天记录”管理页。同一个 QQ 好友或群可拥有任意多份独立记录，支持按 QQ 路由筛选、完整预览、新建、重命名、活动记录切换和整份删除。
- 聊天记录默认滚动到最新消息，右上角“显示楼层”默认只渲染最后 100 条并记住用户设置；参数为非负整数，`0` 表示显示全部。单层编辑框至少保持该楼层编辑前的高度。
- QQ 路由与记录 ID 分离；消息、主动回复和插件生成只读取该路由当前活动记录。记录切换和新消息写入共用路由锁，切换后下一条消息立即生效。
- SQLite WAL、外键、busy timeout 和默认配置种子。
- 启动迁移会移除早期版本遗留在供应商表中的 `temperature` / `max_tokens` 必填列，旧数据库导入新供应商不会再触发 500。
- `uv.lock`、前端锁文件、Windows 自动环境重建与启动脚本。
- 桌面和手机响应式管理界面。
- 管理侧栏顺序调整为配置总览、QQ连接、预设配置、API配置、提示词编辑、用户人设、角色人设、聊天记录、世界书、插件；仅改导航显示名和排序，不改路由或页面内部标题。
- 管理界面已参考本地 LLM 用量统计页的视觉语言改为深色暖金控制台主题：低对比网点背景、深色半透明面板、细描边和暖金主操作色，同时保留蓝/绿/红状态色；侧栏品牌显示为“一只猫娘 / 管理控制台”。
- 控制台右下角提供七段主题色滑块，默认橙色，切换红/橙/金/绿/青/蓝/紫后保存到浏览器本地存储并在刷新后恢复。浏览器 favicon 直接使用用户提供的白底黑边猫娘图片。
- 配置总览的日志消息框会在用户停留底部时继续自动跟随新日志；用户手动向上滚动后保持当前位置，不再被轮询强制拉回底部。
- 发行包不提供自动更新入口，版本文件和用户数据由用户自行管理。

- 第三方插件目录：`data/plugins`；内置插件目录：项目根目录 `plugins`。

## 尚未实现

- NapCat/OneBot 反向 WebSocket 与私聊文本闭环已实现并通过模拟集成测试，但尚未连接用户的正式 NapCat/QQ。
- QQ 收图与单轮多模态已接入；尚未用用户真实 NapCat/供应商验证其图片 URL 访问方式和所选模型的视觉能力。
- 模型运行时已用本地假服务完整验证，但尚未使用用户的真实供应商做 Chat Completions 联调；供应商页面“测试连接”仍只请求 `/models`。
- 已有会话历史、上下文裁剪和每会话串行队列，但尚无 QQ 好友/群聊绑定规则。
- `request_generation` 已会调用模型；`send_text`、`send_image` 在 OneBot 在线时可执行，离线时保持 `pending`。
- 管理界面已有单管理员登录鉴权，但正式公网部署仍需可信反向代理、TLS 和访问来源限制。
- 尚未加入 Alembic 正式迁移、导出文件的一键恢复导入、整库备份恢复和 Windows 服务安装；当前已有受控启动迁移、SillyTavern 导入和项目 JSON 导出。
- Windows 服务安装、健康检查和失败自动回退仍待服务器交付阶段实现，详见 `docs/WINDOWS_DEPLOYMENT.md`。
- 仅按用户明确指定，只读检查了旧 `VirtualCompanion` 的主动回复、晚安和表情回复实现并迁移对应行为与表情资源；没有迁移历史、密钥或旧全局架构。
