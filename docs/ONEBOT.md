# NapCat / OneBot 11 接入

一只猫娘提供 OneBot 11 反向 WebSocket 服务。默认关闭，必须在管理页“QQ 接入”中保存并启用。

## NapCat 连接参数

- 连接类型：反向 WebSocket。
- 地址：管理页显示的 `ws://服务器地址:8732/onebot/v11/ws`；启用 HTTPS 反向代理时使用 `wss://`。
- Access Token：与管理页保存的访问令牌一致。
- NapCat 与一只猫娘不在同一台机器时，地址不能使用 `127.0.0.1`，并需要受控开放对应监听地址、防火墙和反向代理。

服务端接受标准 `Authorization: Bearer <token>`，也兼容 `?access_token=<token>`。启用 OneBot 前必须配置非空访问令牌；未配置令牌的旧数据库会拒绝建立连接。

## 当前消息范围

- 私聊文本：已支持，默认启用。
- 私聊允许名单：留空允许全部；填写后只处理名单中的 QQ 号。
- 群聊文本：已支持但默认关闭。启用后会处理允许群中的全部文本，因此在增加提及/关键词绑定前应谨慎开启。
- 群聊允许名单：留空允许全部群；填写后只处理名单中的群号。
- 收图：已支持 CQ image/mface URL；每条最多 4 张，下载、真实格式识别、像素/边长和压缩限制沿用媒体安全模块。图片只内联到当前模型请求，历史保存相对路径占位符。
- 发图：已支持插件目录或运行数据目录内的 PNG/JPG/JPEG/GIF/WebP 文件路径，最大 32 MB，不使用 base64。

## 消息与动作

QQ 会话 ID：

- 私聊：`qq:{机器人QQ}:private:{用户QQ}`
- 群聊：`qq:{机器人QQ}:group:{群号}`

收到消息后进入统一会话运行时。同一会话串行生成；回复按 4,000 字符分段。表情插件的 `|||` 每段单独发送，文本完成后再发送图片。

同一个 QQ 路由可以有多份聊天记录。OneBot 始终把新事件交给该路由当前选中的记录，切换记录不改变发送目标。

文本在构造 NapCat 请求前会经过 `before_send` 插件钩子。内置“正则”插件只修改这个 QQ 出口副本，规则分为全局和按生成时角色卡 ID 生效的两级；聊天历史、控制台与持久动作保存的仍是原文。

启用分段回复时，内置“正则”插件会先在完整回复上标记所有启用规则匹配范围内的 `|||`，分段插件不会在这些位置拆分。该步骤不执行替换；完整匹配块会保留在同一文本动作中，直到 `before_send` 阶段再由正则处理，因此支持用户自定义的任意包裹标签且不会重复替换。

当前安装已配置一条可单独启停、大小写不敏感且允许跨行的全局正则，用于移除完整 `<Thinking ...>...</Thinking>` 块；出口仍固定移除单独的 `<!-- Test Inputs Were Rejected -->` 标记。整段被清空时动作正常完成，但不会发送空的 OneBot 消息。未闭合的 `<Thinking>` 不会被删除，避免模型截断时误删后续普通回复。

发送使用标准 OneBot 动作：

- `send_private_msg`
- `send_group_msg`

每次调用带唯一 `echo` 并等待 NapCat 回应。`status != ok`、非零 `retcode` 或超时会把动作标记为 `failed`。没有连接时动作保持 `pending`；新连接建立后会重新排队。

## 去重与安全

- 事件优先使用 `{self_id, message_id}` 生成稳定去重键；缺少 message ID 时使用事件字段哈希。
- 去重记录在 `onebot_events` 表，服务重启后仍有效。
- 连接头 `X-Self-ID` 与事件 `self_id` 不一致时拒绝事件。
- echo 只能确认同一条 WebSocket 连接发起的调用。
- Access Token 使用 `data/secret.key` 加密，API 与页面只返回掩码。
- 第三方插件仍与服务进程同权限；发送路径检查不能代替对插件来源的信任。

当前已通过本地模拟 NapCat 的真实 WebSocket 集成测试，覆盖私聊文字、收图多模态、发图路径和 echo，但未连接用户的正式 QQ。正式启用前建议先使用测试 QQ 和私聊允许名单。
