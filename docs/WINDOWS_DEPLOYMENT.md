# Windows 服务器部署与更新设计

## 交付形式

正式部署使用 Windows 发布包，不制作单文件 EXE：

- `安装一只猫娘.cmd`：双击入口，以当前进程范围启动 PowerShell 安装脚本。
- `install.ps1`：检查管理员权限、安装或调用 `uv`、创建锁定的 Python 环境、写入服务配置并注册 WinSW 服务。
- 预构建的 `frontend/dist`：服务器不需要 Node.js 或 npm。
- `uv.lock`：服务器按确定版本重建 Python 环境，不复制开发机 `.venv`。
- WinSW：将程序注册为开机启动、异常自动重启且带日志轮转的 Windows 服务。

不优先使用 PyInstaller 或单文件 EXE。项目允许加载第三方 Python 插件，保留标准 Python 环境更利于插件兼容、依赖审计、故障定位和小步更新。

## 目录隔离

程序版本与持久数据必须分开：

```text
C:\Program Files\Catgirl\
|- current -> releases\<当前版本>
|- releases\
|- updater\
`- service\

C:\ProgramData\Catgirl\
|- data\
|- logs\
|- backups\
`- config\
```

数据库、`secret.key`、用户安装插件、QQ 收图和配置都位于 `C:\ProgramData\Catgirl`，更新时不得放入版本目录或被覆盖。

## 一键更新

更新由主程序之外的 `update.ps1` 执行，避免运行中的程序覆盖自身：

1. 检查更新源和目标版本。
2. 使用 Git fetch 拉取差异对象；正式公开发布后也可使用带哈希/签名的版本清单和发布包。
3. 更新前备份数据库、WAL、SHM、`secret.key` 和配置，并校验备份完整性。
4. 在新的 `releases\<版本>` 目录准备代码、预构建前端和独立虚拟环境，不原地覆盖当前版本。
5. 停止 WinSW 服务，执行受控数据库迁移，再切换 `current` 目录连接。
6. 启动服务并检查 `/health`；失败时自动恢复旧版本目录和升级前数据。
7. 保留最近若干版本，稳定后再清理更旧版本。

用户不需要到网页手工下载、解压和覆盖整个项目。Git 更新只传输仓库中发生变化的对象；已经变化的构建文件仍需要下载，这是任何网络更新都无法省略的部分。

## 更新入口

首个服务器版至少提供：

- `更新一只猫娘.cmd`：双击执行备份、更新、迁移、重启和健康检查。
- `回退一只猫娘.cmd`：选择或自动回退到上一个可用版本。
- 管理界面的“检查更新”只负责展示版本和触发外部更新任务，不让 Web 服务直接以任意参数覆盖程序文件。

正式更新功能上线前，需要先确定代码托管位置、Windows Server 版本、服务账号、安装目录和服务器访问更新源的网络条件。
